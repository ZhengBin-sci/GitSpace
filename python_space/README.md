# UV 项目结构说明与运行指南

##  项目简介

本项目采用现代化的 Python 工程化标准构建，使用 `uv` 作为核心依赖管理与运行工具。项目结构遵循行业标准的 **Src Layout（src 布局）**，旨在通过物理隔离有效避免循环导入、命名空间污染等隐式错误，确保代码在开发、测试和打包阶段的行为高度一致。

##  目录结构说明

```text
project-root/
├── src/                # 核心业务代码目录
│   └── my_package/     # 实际的 Python 包
│       ├── __init__.py
│       └── module.py
├── main.py             # 根目录入口脚本（验证猜想/快速测试）
├── pyproject.toml      # 项目元数据与依赖配置
├── uv.lock             # 依赖锁定文件
└── README.md           # 项目说明文档
```

###  核心设计原则：根目录与 src 的协作

在实际开发与验证过程中，您可能会观察到以下现象：

1. **根目录脚本可直接运行**：放置在项目根目录的脚本（如 `main.py` 或用于验证猜想的临时测试代码），可以直接通过 `uv run python main.py` 执行。
2. **导入路径指向 src**：尽管脚本在根目录，但在代码中 `import` 模块时，Python 解析的包路径实际上位于 `src/` 目录下。

**为什么这样设计？**
这是 `src` 布局的核心优势。当使用 `uv run` 执行根目录脚本时，`uv` 会自动根据 `pyproject.toml` 的配置，将当前项目以“可编辑模式（editable）”安装到虚拟环境中。这使得 `src/` 下的包被安全地注册到 Python 的搜索路径中。这种机制既保留了在根目录编写快速测试脚本的灵活性，又强制要求核心业务代码必须通过标准的包导入方式进行引用，从而杜绝了“因为恰好在同级目录就能 import”导致的隐式依赖问题。

##  快速开始

### 1. 运行根目录脚本
如果您在根目录编写了用于验证想法或快速测试的脚本，请直接使用以下命令：

```bash
uv run python main.py
```

### 2. 运行 src 内的模块
如果您需要以模块方式运行 `src` 目录下的代码，推荐使用 `-m` 参数：

```bash
uv run python -m my_package.module
```

### 3. 执行命令行入口
如果 `pyproject.toml` 中配置了 `[project.scripts]` 入口点，可以直接通过命令名运行：

```bash
uv run my-cli-command
```

## ️ 环境管理

得益于 `uv` 的高效管理，您**无需**手动创建虚拟环境或执行 `pip install -e .`。`uv` 会在首次执行 `uv run` 时自动完成以下操作：
- 读取 `pyproject.toml` 并创建隔离的虚拟环境（`.venv`）。
- 自动安装项目依赖并将本项目以可编辑模式链接。
- 在隔离环境中执行目标脚本。

##  开发建议

- **核心业务代码**：请务必放置在 `src/my_package/` 目录下，并遵循标准的包结构。
- **临时验证脚本**：可暂时放置在根目录，验证完成后建议移入 `tests/` 目录或重构为正式模块。
- **IDE 配置**：在 VS Code 等编辑器中，`uv` 会自动处理 `PYTHONPATH`，通常无需手动配置即可享受完整的代码提示与跳转功能。
